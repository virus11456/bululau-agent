# 布神式幣安 USDT-M 合約策略

這是布神四種型態（布鹿流、大師兄、小師弟、瘸師弟）的策略與執行器骨架，只做多。規則以 2026-11-06 22:23（台北時間）的定稿為準，寫在 [docs/strategy.md](docs/strategy.md)。操作目標在 [docs/operation.md](docs/operation.md)。

**實盤停止，目前只做紙上。** 本倉庫沒有帳戶餘額，也不表示帳戶裡有資金。固定監控要由工程師另寫、完成測試，且使用者確認資金可用之後，才可以重啟實盤。這次沒有新增下單邏輯，也沒有在任何電腦上部署。

合約可以虧掉全部保證金。這不是投資建議。

## 四種型態

| 型態 | 在做什麼 | 常用週期 | 出場（現行） |
|---|---|---|---|
| 布鹿流 | 順勢。第一波之後的回檔，底底高。大約 3 波以上不做 | 1H 以上 | 1.5R 平一半，剩餘移到成本，再依結構移動 |
| 大師兄 | 大週期偏逆勢。長黑後等反彈，二次測前低 | 4H／8H 為主 | 本次不改原文。出場 R 見策略文件的待確認，不平一半 |
| 小師弟 | 急殺後反彈到跌幅的 40–50% 才設計 | 15m | 1.5R 平一半不適用。出場 R 待確認 |
| 瘸師弟 | 爆量長黑之後往下低掛。15m 連續 2–3 根長黑 | 15m | 1.5R 全部平倉，不移停損。不是 2R |

15 分鐘的瘸師弟與小師弟用結構停損，至少 1–2%；BTC、ETH 至少 3%。不套小幣 10% 下限。布鹿流的停損是前低下方 1–2% 容錯，再與 BTC／ETH 3%、小幣 5% 取較寬者。完整條文與出處在策略文件。

## 每 15 分鐘要達成的分工

這是目標，還沒有寫成新的掃描程式。

- 固定程式每 15 分鐘掃全市場。沒有候選就不呼叫 AI，只留一行 log。
- AI 只判斷候選的型態、份數、進場、停損、停利。提示詞在 [docs/agent_prompt.md](docs/agent_prompt.md)。
- 監控程式複核條件、執行風控，並監視停損與停利。複核失敗就丟棄。
- 通過的單先記在紙上。現有的 `position_manager.py` 不是這套監控。

日 K 均線用哪一條、大師兄與小師弟的出場 R、V 轉收不回時怎麼處理、連敗後縮小多少，都在策略文件的待確認區。這些沒有預設數字。

## 設定

金鑰只放本機，不進 git。只開讀取與 USDT-M 合約交易，不要開提現。能綁 IP 就綁工程師的機器，不要連到使用者的電腦。

```bash
cp config.example .env
chmod 600 .env
# 編輯 .env。沒有要讀取帳戶時，可以先留空

mkdir -p data
cp config/events.example.json data/events.json
```

資料目錄預設是專案下的 `data/`。排程若將來啟用，請把 `QUANTBOY_DATA_DIR` 設成絕對路徑。現在不要排程。

## 現有指令

下面的價格只是格式，不是進場建議。不要加上 `--live`。

```bash
python3 src/sentiment.py BTCUSDT
python3 src/prefilter.py --quiet
python3 src/live_trader.py --help
```

`prefilter.py` 結束碼 10 只代表舊篩選有輸出，不等於定稿合格，不應因此呼叫 AI 去下單。結束碼 0 是沒有舊候選。結束碼 2 是行情失敗。

`live_trader.py` 仍然認得 `status`、`open`、`manage`、`watch`、`flatten`。加上 `--live` 會對交易所送出委託。在部署、測試和資金確認完成前，這些實盤子命令保持關閉。

## 安全紅線

只做多。BTC 帶量破關鍵價後兩根 15m 不開多。重大事件前後 30 分鐘不開新倉。當日虧 7% 停開新倉，30% 全停並回報。單筆預估虧損不超過淨值的 1%，停損先掛在交易所。最多 5 個持倉，單幣一個倉。連 3 敗當天停手。風報比不到 1.5 不進。金鑰不進倉庫、不開提現。
