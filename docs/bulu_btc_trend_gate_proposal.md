## 建議寫在哪裡

建議在實盤恢復之前，寫進 `live_trader.py` 的 `cmd_open`，沿用 #46 的位置與模式：

- `setup` 是布鹿流時，讀 BTCUSDT 已收日 K。
- 從歷史逐根走一遍，算出目前是轉多、轉空，或維持上一個狀態。
- 算出來不是轉多，就拒單，記 `bulu_paused_btc_daily_bear`，帶進場、停損、止盈、RR。
- K 線抓不到時 fail-closed，這輪不下布鹿流。

理由：這是下單前最後一道關，不依賴 routine 或 gate 有沒有先擋。

備選是放進 hardfilter。gate 和 hardfilter 要部署的話，需使用者另外同意。這份文件不把那個備選當成已經決定。

## 要幾根 K 線

至少 60 根已收日 K，才算得了 MA60。

建議取 400 根已收日 K。只拿剛滿 60 根時，窗口開頭若不是明確的轉多或轉空，沒有更早的狀態可以「維持上一個狀態」。未收盤的那一根要丟掉。

## 實作時要加的測試

這份提案不改程式。若照上面寫進 `cmd_open`，測試至少要有：

- 收盤 > MA30 > MA45 > MA60：布鹿流照常開單。
- 收盤 < MA30 < MA45 < MA60：不開單，理由是 `bulu_paused_btc_daily_bear`，紀錄裡有進場、停損、止盈、RR。
- 最新一根兩者都不是：沿用上一根已經判定的多或空。
- 從轉空走到「兩者都不是」：仍不開。從轉多走到「兩者都不是」：仍可開。
- 窗口裡還沒出現過轉多或轉空：不是轉多，拒單。

- 大師兄不走這條關卡。
- K 線抓不到，或 418／429：布鹿流這輪不下單。
- 已經開著的布鹿流倉，出場管理不因為轉空而平倉。
