## 11-06 定稿裡的固定掃描目標（尚未作為實盤路徑部署）

這是 11-06 交給工程師的目標，不是現行 routine 的做法。現行是每 15 分鐘（`*/15`，彈性 ±3）先跑 `gate.py`：`QUIET` 不叫 AI，`WAKE` 才審核。不要把下面這套固定掃描寫成已經在跑。

1. 程式抓全市場的 K 線和量。先套 [strategy.md](strategy.md) 的硬條件與各型態篩選：日 K 位置（均線參數未定，見策略文件）、風報比、爆量至少 3 倍、瘸師弟 15 分鐘瞬間單根長黑（BTC／ETH 2%、小幣 4%；2026-11-11 改回布神原文，不再用連續 2–3 根）、布鹿流波數、4H／日 K 的三支吞噬、趨勢是否已有 30–50 根 K、停損後三根、安全紅線。
2. 沒有候選就結束。不呼叫 AI。只記一行 log。
3. 有候選才呼叫 AI，並送上 K 線摘要。AI 只回傳型態、風險份數、進場價、停損價、出場規則。不決定要不要繞過紅線，也不自填待確認區的數字。
4. 監控程式複核：風報比至少 1.5、該型態的停損下限、當天是否已連 3 敗、停損後三根是否走完，以及其他安全紅線。任何一項不通過就丟棄。
5. 通過的單先記在紙上。平倉後沿用檢討：型態、份數、進出場、結果、有沒有照規則。同一個問題大約三次，才考慮寫成新規則；布神沒寫的新規則要使用者同意。

日 K 均線參數還沒有決定。掃描可以附上日 K 的價格與位置，不得用 30／45／60 或其他數字代替，也不得把這一條標成已通過。連敗後縮小金額的比例同樣還沒有數字，確認前只做「連 3 敗當天停手」。

監控程式另外負責已記錄部位的停損與停利：價格碰到紙上停損或停利時記下來，瘸師弟以 1.5R 全平為出場，布鹿流以 1.5R 平一半後依結構移動。大師兄與小師弟的出場 R 仍在待確認，監控程式不要自設一個 R。

這段監控尚未寫進 `src/` 並接到現行 routine。現有 `position_manager.py` 的停利、移保本與時間停損是 2026-10 的參數，不能拿來當這個監控。

## 現有程式的位置

`src/` 是先前的執行器骨架，交易計算在 11-06 那次文件更新沒有改。它和定稿不一致的地方，以策略文件為準，不要在使用時把程式常數當成新規則。現行實盤用的是 Mac 上 `~/quantboy-live/` 的程式，不是假設本倉庫 `src/` 已經自動同步到那台機器。本文件更新沒有改 `src/`，也沒有在任何機器上部署。

| 現有指令 | 說明 |
|---|---|
| `python3 src/prefilter.py --quiet` | 舊篩選。結束碼 0 是它認為沒有候選；結束碼 10 不是定稿合格；結束碼 2 是行情失敗。現行實盤仍暫用 public prefilter，但必須再依定稿審核，不能單靠結束碼 10 開單 |
| `python3 src/sentiment.py 幣種` | 只供對照 11-03 的情緒補充。不下單、不需金鑰。caution 不降份 |
| `python3 src/live_trader.py status` | 會讀帳戶。不要從 box 對使用者實盤帳戶排程 |
| `python3 src/live_trader.py manage` | 不加 `--live` 時不送出委託。7% 仍可能寫入狀態檔。實盤輪次在 Mac 上才加 `--live` |
| `python3 src/live_trader.py open` | 不加 `--live` 時只做計畫與 `/order/test`。實盤必須先 dry-run |
| `python3 src/live_trader.py watch` | 舊的保護單監視。Mac 上現行是每 60 秒加 `--live`。不要在其他地方另排一份 |
| `python3 src/live_trader.py flatten` | 會平掉所有倉並撤掉所有掛單。只在使用者要求或觸發 30% 時用，先 dry-run |
| `python3 src/position_manager.py` | 紙上參數過時，不要拿來做出場 |

同一時間只能有一個 `live_trader.py`。若出現「另一個 live_trader 正在執行」，等它結束，不要改跑 `flatten`。

### 瘸師弟三檔限價（2026-11-13）

不給 `--ladder` 時仍是單張，布鹿流與其他單張的算法不變。三檔只在明確帶這個參數時才走。總量仍用原本的 1% 風險、每份保證金與槓桿上限；進場價改用三檔的 2:3:5 加權均價，再把那個總量拆開。任一檔低於最小量或最小名目，整筆不送。

```bash
python3 src/live_trader.py open \
  --symbol PIEVERSEUSDT --side BUY --entry-type limit \
  --ladder 97,96,95 --stop 92.15 --target 1.5R \
  --setup 瘸師弟 --portion 1
```

`--target 1.5R` 用加權均價算止盈。改成絕對價格也可以。先不要加 `--live`。Mac 上的檔是 `~/quantboy-live/live_trader.py`，不能整份覆蓋；手貼步驟在 [deploy/patches/kuai_ladder_insert.md](../deploy/patches/kuai_ladder_insert.md)。那段新函式不讀金鑰。真正下單仍走該檔自己的金鑰讀取。

`manage` 與 60 秒 `watch` 的排程沒改。有成交時，停損與止盈的數量改成實際持倉，觸發價不重算。持倉歸零且停損或止盈已經不在，才撤掉還沒成交的檔。未成交可以掛多久，程式沒有新的時限。

## 紙上記錄

紙上記錄用資料目錄裡的檔。本倉庫的程式目前不讀這些檔，也不會因此下單。

`cooldowns.json`：停損出場後，同幣要等進場週期的 3 根 K。

```json
{
  "ETHUSDT": {
    "tf": "15m",
    "stopped_at": "2026-11-06T21:15:00+08:00",
    "resume_after_bars": 3,
    "reason": "stop"
  }
}
```

連敗記在 `loss_streak.json`，只記當天已實現的虧損筆數。滿 3 筆，當天不再開新的紙上單。跨日重新計。縮小倉位的比例不要寫死。

事件窗口仍用 `events.json`。可從 `config/events.example.json` 複製。`time_tpe` 不帶時區時當成台北時間。前後各 30 分鐘不開新單。

## 回報

現行實盤 routine：真實開倉、成交、撤單、減倉、移損、平倉、風控或錯誤，以繁體中文回報幣種、價量、停損距離、目標、損益、份數與規則來源。無事安靜。時間標台北時間。不要貼 `.env` 或金鑰。

11-06 目標架構若將來部署：固定掃描沒有候選時不叫 AI，也不要另發「無事」。有候選、被複核丟掉、紙上記錄、出錯或碰到紅線時才回報，並標出處。

## 現有執行器的已知行為

以下是舊程式已經會做的事，供對照。不是新的交易規則。

- 台北時間跨日的第一次 `status`、`open` 或 `manage`，會重寫 `state.json`。`pending` 與 `meta` 會消失。30% 停機旗標檔 `HALT_REPORT_USER.flag` 不會被跨日刪除。旗標還在時，`open` 會拒絕。
- 當日虧損達 7%，狀態裡的停開新倉會打開，下一個台北日隨重置清掉。達 30% 會全平並留下旗標。使用者沒有明確同意之前，不要刪旗標。
- 市價進場後若停損掛不上，程式會市價平掉該倉。限價單的停損預掛失敗時，會撤進場單；已經成交則平倉。止盈失敗但停損還在，倉位會留下並寫錯誤。
- 有倉、沒有停損、狀態裡也沒有停損價時，`--live` 的 manage 會市價平倉。
- HTTP 429、418 或幣安限流會退避。5xx 重試仍失敗就停止。不要在失敗當下改跑 `flatten`。401 或 -2015：停止下單，回報檢查 IP 白名單與權限；不要讀或改金鑰檔。
- 雙向持倉時，`--live` 的開倉會被拒絕。
- 日誌在資料目錄的 `live_log.jsonl`，不要提交。
