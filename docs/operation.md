# 操作架構

策略以 [strategy.md](strategy.md) 的 2026-11-06 定稿為準。

**實盤停止，目前只做紙上。** 本倉庫沒有帳戶餘額，也不表示帳戶裡有資金。下面「固定監控」是交給工程師的目標，這次沒有實作，也沒有在任何機器上部署。不要連到使用者的電腦，不要改使用者既有的紙上目錄。

重啟實盤要五件事都完成：策略已確認、GitHub 已更新、固定監控已部署、測試做完、使用者確認資金可用。在那之前，不要排程，不要加 `--live`，不要把現有程式當成已經在跑的實盤。

## 目標：固定掃描與監控

每 15 分鐘由固定程式做完機械工作。AI 不是每一輪都出現。

1. 程式抓全市場的 K 線和量。先套 [strategy.md](strategy.md) 的硬條件與各型態篩選：日 K 位置（均線參數未定，見下方）、風報比、爆量至少 3 倍、15 分鐘連續 2–3 根長黑、布鹿流波數、4H／日 K 的三支吞噬、趨勢是否已有 30–50 根 K、停損後三根、安全紅線。
2. 沒有候選就結束。不呼叫 AI。只記一行 log。
3. 有候選才呼叫 AI，並送上 K 線摘要。AI 只回傳型態、風險份數、進場價、停損價、出場規則。不決定要不要繞過紅線，也不自填待確認區的數字。
4. 監控程式複核：風報比至少 1.5、該型態的停損下限、當天是否已連 3 敗、停損後三根是否走完，以及其他安全紅線。任何一項不通過就丟棄。
5. 通過的單先記在紙上。平倉後沿用檢討：型態、份數、進出場、結果、有沒有照規則。同一個問題大約三次，才考慮寫成新規則；布神沒寫的新規則要使用者同意。

日 K 均線參數還沒有決定。掃描可以附上日 K 的價格與位置，不得用 30／45／60 或其他數字代替，也不得把這一條標成已通過。連敗後縮小金額的比例同樣還沒有數字，確認前只做「連 3 敗當天停手」。

監控程式另外負責已記錄部位的停損與停利：價格碰到紙上停損或停利時記下來，瘸師弟以 1.5R 全平為出場，布鹿流以 1.5R 平一半後依結構移動。大師兄與小師弟的出場 R 仍在待確認，監控程式不要自設一個 R。

這段監控尚未寫進 `src/`。現有 `position_manager.py` 的停利、移保本與時間停損是 2026-10 的參數，不能拿來當這個監控。

## 現有程式的位置

`src/` 是先前的執行器，交易計算這次沒有改。它和定稿不一致的地方，以策略文件為準，不要在使用時把程式常數當成新規則。

| 現有指令 | 現在能不能用來重啟實盤 | 說明 |
|---|---|---|
| `python3 src/prefilter.py --quiet` | 不能當成 11-06 掃描 | 舊篩選。結束碼 0 是它認為沒有候選；結束碼 10 不是定稿合格；結束碼 2 是行情失敗。沒有候選時本來就不該叫 AI |
| `python3 src/sentiment.py 幣種` | 只供對照 11-03 的情緒補充 | 不下單、不需金鑰。caution 不降份 |
| `python3 src/live_trader.py status` | 不要對著實盤帳戶排程 | 會讀帳戶。本文件不宣稱帳戶有資金 |
| `python3 src/live_trader.py manage` | 不要加 `--live` | 不加 `--live` 時不送出委託。7% 仍可能寫入狀態檔 |
| `python3 src/live_trader.py open` | 不要加 `--live` | 不加 `--live` 時只做計畫與 `/order/test` |
| `python3 src/live_trader.py watch` | 不要加 `--live`，也不要排每分鐘 | 舊的保護單監視，不是 11-06 的固定監控 |
| `python3 src/live_trader.py flatten` | 不要執行 | 會平掉所有倉並撤掉所有掛單 |
| `python3 src/position_manager.py` | 不要拿來做出場 | 紙上參數過時 |

同一時間只能有一個 `live_trader.py`。若出現「另一個 live_trader 正在執行」，等它結束，不要改跑 `flatten`。

金鑰仍只放本機 `.env` 或環境變數，見 [README.md](../README.md)。不要把金鑰寫進 log、提示詞或 git。

## 紙上記錄

在固定監控完成前，紙上記錄用資料目錄裡的檔，程式目前不讀這些檔，也不會因此下單。

`cooldowns.json`：停損出場後，同幣要等進場週期的 3 根 K。

```json
{
  "ETHUSDT": {
    "tf": "15m",
    "stopped_at": "2026-11-06T21:15:00+08:00",
    "resume_after_bars": 3,
    "reason": "stop"
  }
}
```

連敗記在 `loss_streak.json`，只記當天已實現的虧損筆數。滿 3 筆，當天不再開新的紙上單。跨日重新計。縮小倉位的比例不要寫死。

事件窗口仍用 `events.json`。可從 `config/events.example.json` 複製。`time_tpe` 不帶時區時當成台北時間。前後各 30 分鐘不開新單。

## 回報

固定掃描沒有候選時，不叫 AI，也不要另發「無事」給使用者。有候選、被複核丟掉、紙上記錄、出錯或碰到紅線時才回報。回報標出處：【布神原文】、【使用者最新決定】或【我們加的】。

不要在回報裡寫帳戶有資金，除非使用者剛剛給了餘額。不要貼 `.env` 或金鑰。

## 現有執行器的已知行為

以下是舊程式已經會做的事，供工程師對照。不是重新開啟實盤的步驟。

- 台北時間跨日的第一次 `status`、`open` 或 `manage`，會重寫 `state.json`。`pending` 與 `meta` 會消失。30% 停機旗標檔 `HALT_REPORT_USER.flag` 不會被跨日刪除。旗標還在時，`open` 會拒絕。
- 當日虧損達 7%，狀態裡的停開新倉會打開，下一個台北日隨重置清掉。達 30% 會全平並留下旗標。使用者沒有明確同意之前，不要刪旗標。
- 市價進場後若停損掛不上，程式會市價平掉該倉。限價單的停損預掛失敗時，會撤進場單；已經成交則平倉。止盈失敗但停損還在，倉位會留下並寫錯誤。
- 有倉、沒有停損、狀態裡也沒有停損價時，`--live` 的 manage 會市價平倉。這就是現在不能加 `--live` 的原因之一：它會對真實帳戶動作。
- HTTP 429、418 或幣安限流會退避。5xx 重試仍失敗就停止。不要在失敗當下改跑 `flatten`。
- 雙向持倉時，`--live` 的開倉會被拒絕。
- 日誌在資料目錄的 `live_log.jsonl`，不要提交。

## 工程師交接

要寫的是獨立的固定掃描與監控，不是把 `--live` 排進現有 `live_trader.py`。

- 每 15 分鐘全市場掃描。無候選不呼叫 AI。
- AI 只判斷型態、份數、進場、停損、停利。
- 監控程式做條件複核、7%／30%、連 3 敗、事件窗口、停損先掛上的紙上對應，以及停損停利監視。
- 待確認區的四項沒有使用者回覆之前，程式裡不要出現對應的預設數字。
- 部署與測試在工程師的環境完成。不要伸手到使用者的 Mac，也不要改使用者原有的紙上目錄。
- 測試通過且使用者確認資金可用之後，才討論把紙上紀錄接到實盤。接到實盤是下一步，不是這份文件已經完成的事。
